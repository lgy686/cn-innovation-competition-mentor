# 项目接收与材料索引

1. 以当前工作目录为根递归列出文件，排除 `.git`、缓存、临时锁文件和明显生成目录，但保留用户可能作为证据的图片、PDF、Office 文件。
2. 结合目录名、文件名、扩展名和可提取文本，将材料标记为赛事、原始材料、佐证、核心技术参考文献、案例/模板或待判定；一个文件可有多个标签并记录置信度。`参考文献`、`核心技术文献`、`技术文献` 等目录优先判为核心技术参考文献，不能仅因名称含“参考”而归入优秀案例。
3. 优先读取赛事文件的标题、发布日期、赛道、评分、篇幅、格式、匿名、命名和附件要求，再读取与当前任务直接相关的项目文件。处理核心技术章节时，先建立参考文献完整清单；同一主题存在 Markdown 文件时优先阅读 Markdown，再逐一读取 PDF、Word、图片或其他文件，不得因已有 Markdown 而跳过其余文献。
4. 维护“文件清单”和“读取状态”：已读、仅索引、无法解析、需人工查看。无法解析的扫描 PDF、图片或加密文件不得假装已读取。
5. 首次分析至少形成赛事约束矩阵和项目证据矩阵；先向用户报告关键硬约束、缺失材料和口径冲突，再继续可执行部分。

建议输出字段：`path`、`category`、`file_type`、`title_candidate`、`date_candidate`、`readability`、`relevance`、`notes`。可运行 `scripts/inventory_project.py` 获得机器清单。
